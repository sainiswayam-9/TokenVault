================================================================
  SWAGGER UI TEST GUIDE — RBAC PROJECT
  URL: http://localhost:8000/docs
================================================================

HOW TO USE THIS FILE
--------------------
1. Start the API:   uvicorn app.main:app --port 8000 --reload
2. Open:            http://localhost:8000/docs
3. Run Step 0 first (login), then copy the access_token value.
4. Click the lock icon "Authorize" at the top-right of Swagger UI.
5. Paste:           Bearer <paste_token_here>
6. Click Authorize, then Close.
7. Now all protected endpoints will use your token.
8. To test as a different user, repeat from Step 0.

================================================================
  STEP 1 — CSV UPLOAD WORKFLOWS
  Endpoint: /csv/upload
  Auth: ALL roles (salesperson, manager, hr)
================================================================

The form has TWO fields:
  • file     → click "Choose File" and select a .csv file
  • category → type the category name (e.g. leads, sales, employees)

----------------------------------------------------------------
  WORKFLOW A — Upload to a NEW category (creates the file)
----------------------------------------------------------------

[As Alice (salesperson) — Upload ChattySalon.CSV as category "leads"]
POST /csv/upload
  file:     ChattySalon.CSV
  category: leads

Expected response:
{
  "message":    "Category 'leads' created successfully",
  "action":     "created",
  "category":   "leads",
  "rows_added": <number of rows in the CSV>,
  "added_by":   "alice (salesperson)",
  "file":       "uploads/leads.csv"
}

Check the result:
  → Open uploads/leads.csv — every row now has:
       added_by    = "alice (salesperson)"
       uploaded_at = "2026-05-12 06:37 UTC"

----------------------------------------------------------------
  WORKFLOW B — Upload to an EXISTING category (appends rows)
----------------------------------------------------------------

[As Bob (salesperson) — Upload another CSV to the same "leads" category]
POST /csv/upload
  file:     <any other .csv file>
  category: leads

Expected response:
{
  "message":    "Category 'leads' appended successfully",
  "action":     "appended",
  "category":   "leads",
  "rows_added": <number of new rows>,
  "added_by":   "bob (salesperson)",
  "file":       "uploads/leads.csv"
}

Check the result:
  → The existing leads.csv now has MORE rows at the bottom.
  → New rows show added_by = "bob (salesperson)"
  → Original rows still show added_by = "alice (salesperson)"

----------------------------------------------------------------
  WORKFLOW C — Different roles upload to different categories
----------------------------------------------------------------

[As Evan (manager) — Upload to "sales" category]
POST /csv/upload
  file:     <sales data .csv>
  category: sales

[As Diana (hr) — Upload to "employees" category]
POST /csv/upload
  file:     <employee data .csv>
  category: employees

----------------------------------------------------------------
  WORKFLOW D — Error cases
----------------------------------------------------------------

[Upload a non-CSV file — expect 400]
POST /csv/upload
  file:     some_file.xlsx
  category: leads

[Upload an empty CSV — expect 400]
POST /csv/upload
  file:     empty.csv
  category: leads

[Upload without logging in (no token) — expect 403]
  → Remove the Authorize token, then try POST /csv/upload

================================================================
  STEP 5 — DELETE A CATEGORY
  Endpoint: DELETE /csv/{category}
  Auth: manager and hr ONLY (salesperson gets 403)
================================================================

--- As Evan (manager) ---

[Delete the "leads" category]
DELETE /csv/leads

Expected response:
{
  "message":    "Category 'leads' deleted",
  "deleted_by": "evan (manager)"
}

[Verify it is gone]
GET /csv/categories
  → "leads" should no longer appear

[Delete already-deleted category — expect 404]
DELETE /csv/leads

--- As Diana (hr) ---

[HR can also delete categories]
DELETE /csv/employees
Expected response:
{
  "deleted_by": "diana (hr)"
}

--- As Alice (salesperson) — expect 403 ---

[Salesperson CANNOT delete — expect 403]
DELETE /csv/sales
  → Response: 403 Access denied. Required: ['manager', 'hr']. Your role: salesperson

NOTE: Copy an "id" from GET /users/ output for steps below.
Replace <USER_ID> with the actual MongoDB ObjectId string.

[Get single user by ID]
GET /users/<USER_ID>

[Update user password only]
PUT /users/<USER_ID>
{
  "password": "newpassword123"
}

[Update user role only]
PUT /users/<USER_ID>
{
  "role": "manager"
}

[Disable account]
PUT /users/<USER_ID>
{
  "is_active": false
}

[Re-enable account]
PUT /users/<USER_ID>
{
  "is_active": true
}

[Empty update body — expect 400]
PUT /users/<USER_ID>
{}

[Delete user]
DELETE /users/<USER_ID>

[Get deleted user — expect 404]
GET /users/<USER_ID>
