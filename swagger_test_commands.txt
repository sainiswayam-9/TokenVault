================================================================
  SWAGGER UI TEST GUIDE — RBAC PROJECT
  URL: http://localhost:8000/docs

HOW TO USE THIS FILE
--------------------
1. Start the API:   uvicorn app.main:app --port 8000 --reload
2. Open:            http://localhost:8000/docs
3. Run Step 0 first (login), then copy the access_token value.
4. Click the lock icon "Authorize" at the top-right of Swagger UI.
5. Paste:           Bearer <paste_token_here>
6. Click Authorize, then Close.
7. Now all protected endpoints will use your token.
8. To test as a different user, repeat from Step 0.

================================================================
  STEP 1 — CSV UPLOAD WORKFLOWS
  Endpoint: /csv/upload
  Auth: salesperson, manager ONLY
================================================================

The form has THREE fields:
  • file            → click "Choose File" and select a .csv file
  • category        → pick one of: salon, supermarket, pharmacy, electronics, restaurant, others
  • custom_category → required when category is "others"

----------------------------------------------------------------
  WORKFLOW A — Upload to a NEW category (creates the file)
----------------------------------------------------------------

[As Alice (salesperson) — Upload ChattySalon.CSV as category "salon"]
POST /csv/upload
  file:     ChattySalon.CSV
  category: salon

Expected response:
{
  "message":    "Category 'salon' created successfully",
  "action":     "created",
  "category":   "salon",
  "rows_added": <number of rows in the CSV>,
  "added_by":   "alice (salesperson)",
  "file":       "uploads/salon.csv"
}

Check the result:
  → Open uploads/salon.csv — every row now has:
       added_by    = "alice (salesperson)"
       uploaded_at = "2026-05-12 06:37 UTC"

----------------------------------------------------------------
  WORKFLOW B — Upload to an EXISTING category (appends rows)
----------------------------------------------------------------

[As Bob (salesperson) — Upload another CSV to the same "salon" category]
POST /csv/upload
  file:     <any other .csv file>
  category: salon

Expected response:
{
  "message":    "Category 'salon' appended successfully",
  "action":     "appended",
  "category":   "salon",
  "rows_added": <number of new rows>,
  "added_by":   "bob (salesperson)",
  "file":       "uploads/salon.csv"
}

Check the result:
  → The existing salon.csv now has MORE rows at the bottom.
  → New rows show added_by = "bob (salesperson)"
  → Original rows still show added_by = "alice (salesperson)"

----------------------------------------------------------------
  WORKFLOW C — Different roles upload to different categories

[List all users — HR or Manager]

[Create a new salesperson — HR only]
POST /users/
{
  "username": "testuser",
  "password": "test123",
  "role": "salesperson"
}

[Create a new manager — HR only]
POST /users/
{
  "username": "testmanager",
  "password": "manager123",
  "role": "manager"
}

[Create a new HR user — HR only]
POST /users/
{
  "username": "testhr",
  "password": "hr12345",
  "role": "hr"
}

--- Error cases ---

[Invalid role — expect 400]
POST /users/
{
  "username": "baduser",
  "password": "bad123",
  "role": "superadmin"
}

[Duplicate username — expect 409]
POST /users/
{
  "username": "alice",
  "password": "alice123",
  "role": "salesperson"
}

[Password too short — expect 422]
POST /users/
{
  "username": "shortpass",
  "password": "abc",
  "role": "salesperson"
}

NOTE: Copy an "id" from GET /users/ output for steps below.
Replace <USER_ID> with the actual MongoDB ObjectId string.

[Get single user by ID — HR or Manager]
GET /users/<USER_ID>

[Update user password only — Manager only]
PUT /users/<USER_ID>
{
  "password": "newpassword123"
}

[Update user role only — Manager only]
PUT /users/<USER_ID>
{
  "role": "manager"
}

[Disable account — Manager only]
PUT /users/<USER_ID>
{
  "is_active": false
}

[Re-enable account — Manager only]
PUT /users/<USER_ID>
{
  "is_active": true
}

[Empty update body — expect 400]
PUT /users/<USER_ID>
{}

[Delete user — Manager only]
DELETE /users/<USER_ID>

[Get deleted user — expect 404]
GET /users/<USER_ID>
